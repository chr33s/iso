Your editor. Their VM.

Open the project's VM with iso code . or iso zed .. By default, the editor runs in a fresh sandbox with no access to your host files, keychain, or clipboard.

See editor integration

Limit the network.

Set egress to none to cut routes beyond your Mac, or filtered to allow only listed hosts. Guests can still reach services on the Mac itself.

Read about egress

Secrets and an audit trail.

iso secrets encrypts local secrets with a passphrase and this Mac’s Secure Enclave key. iso audit records boundary events and variable names, never values.

More ways to make it yours

Pick your guest. Choose your workflow.

Run on your Mac or a trusted remote Mac. Choose your model, set rules for access, and keep a working environment ready for the next session.

iso setup --guest macos

Linux or macOS.

Build a macOS template from an Apple restore image you supply, then launch Claude Code or Codex inside it. Linux remains the default.

Set up a macOS guest
iso host up

Use another Mac.

Run a Linux VM on another trusted Apple Silicon Mac over SSH. Keep your terminal and editor local, with provider credentials held by your client’s proxy.

Connect a remote Mac
iso policy show

Set rules at the boundary.

For local VMs, opt into default-deny rules for provider access and applying staged files. Add proxy request limits and require a fresh, single-use approval before each apply.

Explore authorization policy
iso model set local

Cloud or a local model.

Route agents to a configured model server on your Mac, and switch back to cloud defaults without rebuilding the VM. Relaunch the agent to use the new configuration.

Configure local models

Less access. On purpose.

The provider-only preset disables direct guest internet access, requires the credential proxy, and stages file returns. Set a session deadline, too.

proxy requiredstaged pulls8h session TTL

Hardening is opt-in; the default is networked. No-egress mode can still reach services on your Mac. A VM is a boundary, not a guarantee. Read the trust model →

python3 scripts/build-release.py --release

Extract the archive in .build/release-archive/ and install all five executables (iso, iso-proxy, iso-egress, iso-sandbox, iso-macos-helper) together on PATH. The Apple container service and guest kernel are also required. Backend setup → 

iso setup
cd ~/code/my-project
iso up

Run after installing the binaries. iso code and iso zed open the project's VM in your editor over SSH. Configure provider authentication before launching your agent. Configuration guide →
