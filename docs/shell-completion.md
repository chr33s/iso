# Shell completion

`coop completions <shell>` prints a static completion script for **bash**, **zsh**, or **fish**, generated by Swift Argument Parser. It completes subcommands, options, and fixed option values. Generating it loads no configuration or secrets, touches no state, and does not invoke the runtime.

## Static completion

Generate a script once and drop it where your shell looks for completions.

### bash

```sh
mkdir -p ~/.local/share/bash-completion/completions
coop completions bash > ~/.local/share/bash-completion/completions/coop
```

System-wide variant:

```sh
coop completions bash | sudo tee /etc/bash_completion.d/coop > /dev/null
```

### zsh

The completion file must live on `$fpath`. If you don't already have a directory for it:

```sh
mkdir -p ~/.zfunc
echo 'fpath=(~/.zfunc $fpath)' >> ~/.zshrc
echo 'autoload -Uz compinit && compinit' >> ~/.zshrc
coop completions zsh > ~/.zfunc/_coop
```

### fish

```sh
coop completions fish > ~/.config/fish/completions/coop.fish
```

Restart the shell (or `source` your rc) after the first install.

## What is not completed

There is no dynamic completion: instance, image, and profile names are not
completed, and the former `COMPLETE=<shell>` hook is gone (remove any
`source <(COMPLETE=… coop)` line from your shell rc). List those names with
`coop list`, `coop images`, and `coop profiles list`.

PowerShell and Elvish scripts are no longer generated; `coop completions
powershell` or `coop completions elvish` fails with an error naming the
supported shells.
